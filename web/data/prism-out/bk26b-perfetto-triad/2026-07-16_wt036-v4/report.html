§0 结论先行：三层问题叠加把帧率从 60fps 压到 21fps

三条按强度排序的独立结论，每条配 ASCII 图 + 关键数字 + 详见 §X 引用。这不是单一元凶，是 GPU 等待 + 降频 + 业务稳态成本三层叠加。

① 主线程瓶颈形态演化：从 base 的'几乎全程在算'到 throttle 的'半睡型'——核心增量是等 GPU 严重

throttle 态主线程 39% 时间在 Sleeping，其中绝大多数是在等 GPU 完成渲染。单次 Gfx.WaitForPresentOnGfxThread 平均等 17.8ms，已经超过一个 60Hz vsync 周期（16.66ms），说明 GPU 撑爆了 swapchain 排队——这是 throttle 从 33fps 进一步跌到 21fps 的第一主因。详见 §3。

② 降频形态：大核被压到 59% + 中核 max-freq 被压到 2227MHz——SoC 热保护已介入 高

throttle 态 SoC 大核频率仅达理论上限的 59.2%（严重低频），中核 cpu4-6 的观测 max 频率从 cur 的 2342MHz 降到 2227MHz（低于 cpuinfo 上限 2419MHz），是 SoC 主动压低 max-freq 的间接证据。三态 bigCoreReach 74.9%→75.6%→59.2% 单调下降，配合主线程 Sleeping 暴涨，构成 likely 档降频判定（缺温度信号无法升到 confirmed）。详见 §4。

采集元信息 信息

§2 多线程宏观：主线程变慢，Render 线程变闲，Audio 池全程睡

每个识别到的线程一行三态健康度。主线程 Run 三态单调下降 Sleep 单调上升，Render 线程同步变闲（throttle 最闲 16.71%），Audio 线程池 5 个子线程 Sleep 全 ≥94% 已排除，AsyncWorker Sleep 99.88% 已排除。无 ECS Worker/LuaMtGC/RHI 独立线程——本次是非典型 Unity 采集。

多线程宏观 信息

§3 主线程 off-CPU 归因：39% Sleep 中 89% 是等 GPU，binder/锁已排除

用 byState 分布 + wait slice 重叠法做归因。throttle 态主线程 Sleeping 38.99%，其中 byState.S 占 off-CPU 的 89.34%——宏观归因是等 GPU。微观层 Gfx.WaitForPresentOnGfxThread 单次 17.8ms（超 vsync），count=427 与帧数一致（每帧都在等）。D 状态仅 1.3% 排除 binder/锁，R+ 涨 ×6.6 是降频期间任务排队的弱辅助信号。

byState 分布 + wait slice 重叠法归因 严重

throttle 态主线程 Sleeping 38.99%。byState 分布：S（可中断睡眠）占 off-CPU 的 89.34%——这是宏观归因层，指向等 GPU。D（不可中断睡眠，含 binder/IO/锁）仅 1.3%，排除 binder IPC 阻塞和锁等待。R+（被抢占）从 base 0.42% 涨到 throttle 2.78%（×6.6），与大核频率不足、任务排队增多一致，是弱辅助信号。
微观层 wait slice 重叠法：Gfx.WaitForPresentOnGfxThread avg=17.799ms，单次已超过 60Hz vsync 周期 16.66ms（强信号阈值），count=427 与 PlayerLoop 帧数一致（每帧都在等）。三态演化：base avg 0.905ms → cur 5.834ms → throttle 17.799ms，cur→throttle foldChange=2.697（涨 ×2.7），avgMs 增量 +11.965ms/帧。URP.AfterRendering 占比从 cur 22.5% 涨到 throttle 41.36%（foldChange 2.501），其中 URP.Submit 40.43%、URP.WaitForPresent 38.12%——渲染等待是 throttle 帧时增量的核心。

§4 降频时序：大核+中核集群同时被压，likely 档（缺温度确认）

三态对照 bigCoreReach + per-CPU 实测 + 降频判定矩阵。大核 cpu7 reach 三态 73.7%→77%→61.4%，中核 cpu4-6 observed max 2419→2342→2227MHz（cpuinfo 上限始终 2419MHz）——observed max 低于 cpuinfo max 是 SoC 主动压低 max-freq 的间接证据。无 thermal sidecar，无法用温度 Δ 做第二信号确认，定 likely 档。

降频判定矩阵 高

四信号同向判定：(1) bigCoreReach 三态 74.9%→75.6%→59.2%，throttle 跌破 65% 严重低频线（DR-42 单态阈值 <65%）。(2) 中核 cpu4-6 observed max 2419→2342→2227MHz，cpuinfo 上限始终 2419MHz——observed max 低于 cpuinfo max 是 SoC 主动压低 max-freq 的间接证据。(3) big 核 cpu7 reachPct 73.7%→77%→61.4%，throttle 跌幅最大。(4) R+（被抢占）从 base 0.42% 涨到 throttle 2.78%（×6.6），与降频期间任务排队一致。
形态识别：base/cur bigCoreReach 74-76%（弱信号，负载-频率背离但未严重），throttle 跌到 59.2%（严重低频）——形态是'压测持续后 SoC 主动压频压温度'。主线程 runningPct 三态 86.94%→77.82%→56.99% 单调下降，sleepingPct 12%→20.4%→38.99% 单调上升，与降频趋势同向。
诚实声明：本 trace 无 thermal sidecar（thermal_before/after.txt 文件不存在），温度信号缺失，无法用'温度 Δ≥5°C 或采后≥75°C'做第二信号确认，降频定 likely 档而非 confirmed。R+ 涨 ×6.6 是弱辅助信号（占比小 2.78%）。

§6 GPU-bound 判定：throttle 强/cur 中等/base 健康，硬证给不出

多信号同向判定 GPU-bound。throttle 强信号（单次 wait > vsync + Render 变闲 + Choreographer 稳 + binder 低 + ECS 均衡），cur 中等信号（wait 5.8ms 未超 vsync 但已显著），base 健康信号（wait 0.9ms，GPU 跟得上）。诚实声明：本 trace 无 GPU busy/freq counter，'GPU 100% 满载'的硬结论给不出，只能停在间接强信号档。

Gfx.WaitForPresent 单次 avg 演化 + GPU bound 判定矩阵 严重

Gfx.WaitForPresentOnGfxThread 单次 avg 三态演化：base 0.9ms → cur 5.8ms → throttle 17.8ms。对照 vsync 周期 16.66ms：base/cur 未超（GPU 跟得上），throttle 单次 17.8ms 超过一个 vsync 周期（GPU 撑爆 swapchain）。count=427 与 PlayerLoop 帧数一致（每帧都在等）。
RHI/Render 顶层辅证：UnityGfxRenderS runningPct 三态单调下降 25.98%→22.3%→16.71%，throttle 最闲——CPU 渲染命令录制不是瓶颈，GPU 在拖。Choreographer 三态都稳在 60.1fps、slowFrameRate=0，排除 SurfaceFlinger/vsync 问题。byState.D 仅 1.3%，排除 binder/锁。无 ECS Worker 线程、无 LuaMtGC 线程，排除 Job 不均和 Lua GC spike。
