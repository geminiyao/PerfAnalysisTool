§0 结论先行：三态退化故事与三条核心结论

本次采集是 AOE3D 大地图行军压测的三态对照：base 空场景 60fps → cur 进入行军 33fps → throttle 持续压测后 21fps。98.83% 帧超 16.67ms 预算，p50 从 16.69ms 涨到 45.94ms。这不是单一元凶，而是 GPU 等待（throttle 主因）+ 业务脚本稳态税（每帧 24%）+ SoC 降频（加剧 GPU 等待）三者叠加。以下三条结论按对整体帧率的贡献排序。

① 主线程瓶颈形态：从 base 的'几乎全程在算'到 throttle 的'半睡型'——核心增量是等 GPU 严重

> 🔴 throttle 态主线程有 39% 时间在 Sleeping，单次等 GPU 17.8ms 已超过一个 vsync 周期（16.66ms），GPU 撑爆了 swapchain 排队。

§2 多线程宏观：主线程变闲、渲染线程更闲

本次 trace 线程类型简单：主线程 + 渲染线程 + Audio 线程池 + AsyncWorker。三态演化最显著的特征是主线程和渲染线程的 runningPct 单调下降——主线程从 87% 跌到 57%（sleeping 从 12% 涨到 39%），渲染线程从 26% 跌到 17%。两者同向变闲，说明不是 CPU 渲染命令录制瓶颈，而是 GPU 在拖（详见 §6）。Audio 线程池和 AsyncWorker 全程 Sleep ≥94%，已排除。

§4 降频时序：大核频率被压到 59%

throttle 态 SoC 大核频率仅达理论上限的 59.2%，中核 cpu4-6 的观测 max 频率从 base 的 2419MHz 降到 2227MHz（cpuinfo 上限始终 2419MHz）——observed max 低于 cpuinfo max 是 SoC 主动压频的间接证据。三态 bigCoreReach 74.9%→75.6%→59.2% 单调下降，与主线程 sleeping 暴涨同向。

信号判定档证据
大核 bigCoreReach 59.2% likely cpu7 reach 三态 73.7%→77%→61.4%，throttle 跌破 65% 严重低频线
中核 max-freq 被压到 2227MHz likely cpu4-6 observed max 三态 2419→2342→2227MHz，cpuinfo 上限始终 2419MHz——SoC 主动压频间接证据
R+ 被抢占暴涨 ×6.6 suspected 主线程 R+ 从 base 0.42% 涨到 throttle 2.78%，与降频期间任务排队增多一致（弱辅助信号）
温度信号缺失 suspected thermal sidecar 文件不存在，无法用温度 Δ 做第二信号确认，判定停在 likely 档
降频形态识别与判定矩阵 高

形态识别：base/cur bigCoreReach 74-76%（弱信号，负载-频率背离但未严重），throttle 跌到 59.2%（严重低频）——形态是'压测持续后 SoC 主动压频压温度'。
per-CPU 实测对照（throttle）：
- cpu7（大核）：avg 1744MHz，max 2841.6MHz，reach 61.4%
- cpu4-6（中核）：avg 1268.6MHz，max 2227.2MHz（cpuinfo 上限 2419MHz），reach 57%，reachVsCpuinfo 52.4%
- cpu0-3（小核）：clusterSummary 67.9%
中核 max 被压到 2227MHz（cpuinfo 2419MHz）说明 SoC 热管理已介入中核集群，不只是大核。R+（被抢占）从 base 0.42% 涨到 throttle 2.78%（×6.6），与降频期间大核频率不足、任务排队增多一致。
诚实声明：本 trace 无 thermal sidecar（thermal_before/after.txt 文件不存在），温度信号缺失，无法用'温度 Δ≥5°C 或采后≥75°C'做第二信号确认，判定停在 likely 档（confidence medium）。

cur 态 PlayerLoop p50=30.15ms，Core.Update 每帧平均 7.32ms 占 24.1%——是稳态业务成本大头。下钻 Core.Update 内部：LuaMgr（Lua 业务调度层）占 12.5%，MapManager 占 9.5%（含行军线管理 5.19%）。这些不是尖峰而是每帧都跑的持续成本，throttle 态因帧时拉长占比略降但绝对量仍在。
