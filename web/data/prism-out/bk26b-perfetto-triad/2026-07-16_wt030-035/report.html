§0 结论先行：三股力量在 throttle 态汇合

throttle 态 21fps 不是单一元凶，是 GPU 溢出（主线程 39% 睡等 GPU）+ SoC 降频放大（大核 59%）+ 业务稳态税（Core.Update 24%）三股力量叠加；base 态刚好踩 60fps 预算线（p50 16.69ms），cur/throttle 是负载加上去后的退化结果。

① GPU-bound：throttle 主线程 39% 时间在等 GPU（第一主因） 严重

throttle 态主线程 Sleeping 38.99%，其中 Gfx.WaitForPresentOnGfxThread 单次 avg 17.8ms 已超过 60Hz vsync 周期 16.66ms——意味着 GPU 一帧渲染时间已超 16.67ms 预算，swapchain 排队被撑爆。三态演化 base 0.9ms → cur 5.8ms → throttle 17.8ms，cur→throttle foldChange ×2.7。427 帧每帧都在等（count=427 与帧数一致），不是偶发是稳态。这是 throttle 从 33fps 跌到 21fps 的直接原因。

优化建议
  1. 降低 GPU 负载：检查 DrawCall 数量、Shader 复杂度、渲染分辨率（AOE3D 移动端默认 900p，可考虑降档）、overdraw
  2. URP.AfterRendering 占 41% 是渲染等待集中点但无子 marker，需补 PostProcessing/Blit/FinalBlit 的 Profiler marker 才能给更细建议
  3. base 态 URP.Render 已占 36% 但 GPU 跟得上（wait 仅 0.9ms），说明渲染负载本身不轻；cur/throttle 加了战斗/行军实体后 GPU 溢出，需看战斗场景的渲染对象增量（部队模型、特效、行军线）
② Core.Update 稳态占 24%：LuaMgr + MapManager 是大头（第二成本） 高
