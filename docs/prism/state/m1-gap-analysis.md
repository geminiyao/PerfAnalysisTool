## 二、逐个 M1 需求的真实状态（校准 backlog 旧描述）

### BK-15 线程/URP 收敛偏见 —— 🟡 **大部分已解决**（backlog 描述已过时）
- backlog 旧описание："线程账只字未提、URP整树当噪音丢"。
- **实测**：这版 HTML **已有**"工作线程与跨线程等待：主线程之外还发生了什么"分群，明说"别只盯主线程"，且抓到"LuaMtGc 拖累主线程 WaitGCThread 等待（100%重叠）"这条跨线程因果链；URP 有独立发现且被正确辨伪为"正常渲染负载非bug"。
- **残留缺口**：需复核——(a) 除 LuaMtGc 外，Job.Worker / Submit / Render Thread 的账是否也落实了？(b) 主线程 Semaphore 等待 1042ms 是否追到了"在等哪根线程的哪个 Job"（DR-17④等待链反查 BK-6 的范畴）？
- **判断**：BK-15 的核心（工作线程分群）已兑现，剩的是"等待链深挖"，与 BK-6 合并更合适。**不需大改 prompt，需小幅强化 + 验证覆盖。**

### BK-20 单源三维热点判定 —— 🟡 部分覆盖
- **实测**：已按"贡献度"排序（topConclusions 有 contribution 字段说明"占全部极慢帧70%"/"累计1381ms决定天花板"），已辨伪。
- **缺口**：三维（绝对量/占比/离群度）是**隐式**用的，没有显式"这是绝对量大/占比高/离群严重哪一类"的标注；也没有"整体达标判定用帧预算(能判)、单marker该不该管(单源判不了)"的诚实声明。
- **判断**：内核逻辑基本在，缺"显式化 + 诚实标注"这层表达。

### BK-16 源码归因 miss —— ❌ **仍真缺**（报告自己承认）
- **实测**：report.md 发现2 明说"getSourceForSymbol 未能精确解析 OnCameraMove（返回 ambiguous，5个候选），无法给行级建议"；发现1/4/6 也多次"未能获取…需 data-requests"。
- **判断**：这是**最硬的真缺口**，报告的建议质量卡在这里。Lua 裸名消歧 + 调用栈辅助定位。

### BK-17 HTML 结构美化 —— 🟡 部分缺
- **实测**：有分群标题、火焰条、色块、字号已有多级（10-24px）。
- **缺口**：**无目录/章节导航**（`grep href="#"` = 0），长报告不能快速跳转。这是明确要补的。
