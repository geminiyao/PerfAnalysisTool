§2 多线程宏观：线程类型简单，UnityGfxRenderS 反向印证 GPU-bound

本次 trace 线程类型简单：UnityMain + UnityGfxRenderS + Audio 线程池 + AsyncWorker。无 ECS/LuaMtGC/RHI 独立线程。UnityGfxRenderS running 三态单调下降是 GPU-bound 的反向辅证（CPU 渲染命令录制越来越闲 = GPU 在拖）。

所有识别线程三态健康度表 信息

UnityMain（主线程，业务/Lua/ECS 调度主入口）：running 86.94%→77.82%→56.99% 单调下降，sleeping 12.04%→20.40%→38.99% 单调上升——throttle 半睡型，Sleep 增量几乎全部是等 GPU。UnityGfxRenderS（渲染命令录制层，等主线程发命令）：running 25.98%→22.3%→16.71% 单调下降，throttle 最闲——CPU 渲染命令录制不是瓶颈，GPU 在拖。Audio 线程池（AAudio_1/AudioTrack/Audio Mixer/Audio Stream/GVoiceRender）：Sleep 全 ≥94%，running <4%，非瓶颈。AsyncWorker：Sleep 99.88%，running 0.05%，非瓶颈。

§3 主线程 off-CPU 归因：throttle 39% Sleeping，89% 是等 GPU

wait slice 重叠法是核心证据：throttle 主线程 Sleeping 38.99%，byState.S 占 off-CPU 的 89.34%（宏观归因）；微观层 Gfx.WaitForPresentOnGfxThread 单次 avg 17.8ms（超 vsync），count=427 与 PlayerLoop 帧数一致（每帧都在等）。

byState 分布 + wait slice 重叠 + 因果链 严重

throttle 主线程 off-CPU 归因：S 状态 89.34%（宏观层归因到等 GPU）+ D 状态 1.3%（binder/IO/锁，排除）+ R 状态 6.58%（就绪但未跑到，与大核频率不足有关）+ R+ 2.78%（被抢占，×6.6 涨）。wait slice 微观层：Gfx.WaitForPresentOnGfxThread avg 17.8ms / count 427（每帧都在等，单次超 vsync）⊂ URP.WaitForPresent avg 3.56ms / count 2135（父 slice，父子重叠所以 totalMs 口径 >100%）。因果链：主线程发起渲染 → URP.Render → URP.AfterRendering（throttle 占 41.36%，cur 22.5%，foldChange 2.5）→ URP.WaitForPresent → Gfx.WaitForPresentOnGfxThread → 等 swapchain → GPU 完成。注意 waitSliceTotalMs/sleepingMs 口径 691% 是因为父子 slice 重叠，用已剥洋葱的 byState.S pctOfOffCpu=89.34% 做宏观归因。

§4 降频时序：大核 59% + 中核 max 被压，likely 档降频

三态 bigCoreReach 74.9%→75.6%→59.2%，throttle 跌破 65% 严重低频线。中核 cpu4-6 观测 max 从 2419/2342 降到 2227MHz（cpuinfo 上限 2419 不变 = SoC 主动压低 max-freq）。无 thermal sidecar，定 likely 档。

per-CPU reach% + 形态 + 判定矩阵 高

降频形态：base/cur bigCoreReach 74-76%（弱信号，负载-频率背离但未严重），throttle 跌到 59.2%（严重低频）——形态是'压测持续后 SoC 主动压频压温度'。per-CPU 实测：cpu7 (大核) avg 1744 / max 2841 / reach 61.4%；cpu4 (中核) avg 1268 / max 2227 / reach 57% (cpuinfo 2419，reachVsCpuinfo 52.4%)。中核集群 max 被压到 2227 < cpuinfo 2419 = SoC 热管理已介入中核集群，不只是大核。R+（被抢占）从 base 0.42% 涨到 throttle 2.78%（×6.6），与降频期间大核频率不足、任务排队增多一致。判定矩阵：bigCoreReach 跌破 65% (confirmed signal) + 中核 max 下降 (confirmed signal) + 温度信号缺失 (missing) = likely 档降频，confidence medium。

§5 主线程一帧时间去向：Core.Update 24% 是稳态业务大头

cur 态 PlayerLoop p50 30.15ms，Core.Update avg 7.32ms 占 24.11%（远超 5% 红线）。下钻：LuaMgr 12.5% + MapManager 9.5%（含行军线 5.19%，唯一涨幅显著 ×1.37）+ BattleHeadMgr 4.92% + MapSignificanceMgr 3.99%。base 是空场景无业务模块，foldChange 不可用，用 cur 占 p50 百分比判定。

Core.Update callTree 缩进树 + 红线模块下钻 高

cur 态 Core.Update 7.32ms/帧（占 p50 24%）：CS:AOE.LuaMgr 3.80ms（12.5%，Lua 业务主入口 OnTick&UpdateSchedule）/ CS:AOE.Outside.MapManager 2.90ms（9.5%，含 OutSideViewArmyLineMgr 1.575ms 行军线管理 cur→throttle 涨 ×1.37 + BattleUIManager 0.72ms + MapEntityEffectMgr 0.24ms）/ BattleHeadMgr 1.51ms（4.92%，战斗头部管理 OnUpdate）/ MapSignificanceMgr 1.21ms（3.99%，地图 AOI，ProcessTasks → ProcessTask_MapObjRefresh 2.06% + ProcessTask_MapEntityAdd 0.67%）。OutSideViewArmyLineMgr 是 cur→throttle 唯一涨幅显著的业务模块（+0.865ms/帧），但该节点是叶子无子 marker，queryCallTreeSubtree 显示它调用 OutsideLineCtrl:CalculateVertexJob (Burst)（count=57820，totalMs 206.86）——顶点计算是子任务之一，但无法拆分是顶点/线段/渲染提交哪个贵。MapSignificanceMgr.ProcessTasks 已钻到 ProcessTask_MapObjRefresh 叶子（count=2379，avgMs 0.127，每帧调用 4.9 次）——刷新频率可评估是否过高。
