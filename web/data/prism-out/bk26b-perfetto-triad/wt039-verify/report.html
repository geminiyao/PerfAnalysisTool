§0 结论先行：三力同向叠加，throttle 态从 33fps 跌到 21fps

这不是单一元凶，是 GPU 撑爆 + SoC 降频 + 业务稳态税 三力同向叠加。按对整体帧率贡献排序：GPU 等待（critical）> 降频（high）> 业务脚本（high）> GC 尖峰（medium）> 线程覆盖声明（info）。

> throttle 态主线程 38.99% 时间在等 GPU，单次等 17.8ms 已超过一个 vsync 周期——GPU 撑爆了 swapchain 排队。
关键数字：
- 主线程 Sleeping 三态 12.04% → 20.40% → 38.99%（单调上升）
- Gfx.WaitForPresent 单次 avg 三态 0.9 → 5.8 → 17.8ms（cur→throttle 涨 ×2.7）
- byState.S 占 off-CPU 的 89.34%（Sleep 增量几乎 100% 是等 GPU）
详见 §3。

§3 主线程 off-CPU 归因：38.99% Sleeping 中 89.34% 是等 GPU

throttle 态主线程 38.99% 时间在 Sleeping，byState 显示 S 状态占 off-CPU 的 89.34%（宏观归因）。微观层在 waitSlices 里找 GPU 等待 slice：Gfx.WaitForPresentOnGfxThread avg=17.8ms，单次已超过 60Hz vsync 周期 16.66ms，count=427 与 PlayerLoop 帧数一致（每帧都在等）。

byState 分布：S 状态占 off-CPU 的 89.34% 高

throttle 态主线程 off-CPU 时间按状态分解：S（可中断睡眠）89.34%、D（不可中断睡眠）1.3%、R（运行）6.58%、R+（被抢占）2.78%。S 状态占绝对大头，宏观归因指向"在等某个事件"。D 状态仅 1.3% 排除 binder/IO/锁阻塞，R+ 从 base 0.42% 涨到 throttle 2.78%（×6.6）与降频期间大核频率不足、任务排队增多一致。

§7 ROI 优化方向：按 severity + 贡献排序
