主题分群
§0 结论先行

三态从 60fps 退化到 21fps，三股力量叠加：GPU 撑爆 swapchain（throttle 主因）、SoC 大核降频（加剧 GPU 等待）、业务脚本 Core.Update 稳态占 24%（每帧常驻税）。以下三条按对整体帧率的贡献排序——稳态大头和高频瓶颈排前，罕见尖峰（GC）排后。

① GPU-bound：throttle 态主线程 39% 时间在等 GPU，单次等 17.8ms 超过一个 vsync 周期 严重

throttle 态主线程 Sleeping 38.99%（vs base 12.04%），其中绝大多数是在等 GPU 完成渲染——单次 Gfx.WaitForPresentOnGfxThread 平均等 17.8ms，已经超过一个 60Hz vsync 周期（16.66ms），说明 GPU 一帧渲染时间已超预算，撑爆了 swapchain 排队。这是 throttle 态从 33fps 进一步跌到 21fps 的主因。三态演化：base avg 0.9ms → cur 5.8ms → throttle 17.8ms，cur→throttle 涨 ×2.7。多信号同向验证：Render 线程 UnityGfxRenderS running 三态单调下降 25.98%→22.3%→16.71%（throttle 最闲，CPU 渲染命令录制不是瓶颈，GPU 在拖）；Choreographer 三态稳在 60fps 排除 SurfaceFlinger；D 状态仅 1.3% 排除 binder/锁；无 ECS/LuaMtGC 线程排除 Job 不均和 Lua GC spike。

② SoC 降频：throttle 态大核频率被压到 59%，中核 max 频率从 2419→2227MHz 高

throttle 态 SoC 大核频率仅达理论上限的 59.2%（严重低频），中核 cpu4-6 的观测 max 频率从 cur 的 2342MHz 降到 2227MHz（低于 cpuinfo 上限 2419MHz），是 SoC 主动压低 max-freq 的间接证据。三态 bigCoreReach 74.9%→75.6%→59.2% 单调下降，配合主线程 Sleeping 暴涨，构成 likely 档降频判定。R+（被抢占）从 base 0.42% 涨到 throttle 2.78%（×6.6），与降频期间大核频率不足、任务排队增多一致。降频是 SoC 热保护行为，根因是持续高负载导致温度累积——降低整体 CPU/GPU 负载是治本（见 ① 和 ③ 的优化方向）。缺 thermal sidecar，无法升到 confirmed。

③ 业务脚本 Core.Update 稳态占 24%：LuaMgr + MapManager 是大头（行军线管理 cur→throttle 涨 ×1.37） 高

cur 态 Core.Update 每帧平均 7.32ms、占 PlayerLoop p50 的 24.11%（远超 5% 红线），是稳态业务成本第一大头。其中 LuaMgr（Lua 业务主入口）占 12.5%、MapManager 占 9.5%（含行军线管理 OutSideViewArmyLineMgr 5.19%）。这些不是尖峰而是每帧都跑的持续成本。行军线管理是 cur→throttle 唯一涨幅显著的业务模块（×1.37，+0.865ms/帧），throttle 态因帧时拉长占比略降但绝对量仍在。base 是空场景无业务模块，cur/throttle 才进入战斗/行军压测场景，业务模块从无到有，foldChange 不可用，用 cur 态占比判定。
