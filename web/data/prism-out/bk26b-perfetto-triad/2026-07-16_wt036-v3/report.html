§0 结论先行：三态退化故事 + 三条独立结论

三态从 base 的 60fps 健康态退化到 throttle 的 21fps 严重退化态，背后是三个独立机制叠加——GPU 撑爆、SoC 降频、稳态业务税。按强度排序三条结论如下。

① 主线程瓶颈形态：从 base 的'几乎全程在算'到 throttle 的'半睡型'——核心增量是等 GPU 严重

> 🔴 throttle 态主线程有 38.99% 时间在 Sleeping，单次 Gfx.WaitForPresentOnGfxThread 平均等 17.8ms，已超过 60Hz vsync 周期 16.66ms，427 帧每帧都在等——GPU 撑爆了 swapchain 排队。
>
> 关键数字：Gfx.WaitForPresent 占整 trace base 5.4% → cur 19.3% → throttle 38.1%（Sleep 增量几乎 100% 是等 GPU）。详见 §3。

§3 主线程 off-CPU 归因：byState + wait slice 重叠 + 因果链

throttle 态主线程 Sleeping 38.99%，byState 显示 S 状态占 off-CPU 的 89.34%（宏观归因）。微观层在 waitSlices 里找 GPU 等待 slice：Gfx.WaitForPresentOnGfxThread avg 17.8ms（单次超 vsync），count=427 与 PlayerLoop 帧数一致（每帧都在等）。

throttle 一帧的等待因果链：主线程发起渲染 → 等 swapchain → GPU 撑爆 严重

> 🔴 throttle 态主线程 Sleeping 38.99%，其中 byState.S 占 off-CPU 的 89.34%——宏观层归因是 Sleep（可中断睡眠，等 GPU/锁/信号量）。微观层在 waitSlices 里找：Gfx.WaitForPresentOnGfxThread avg 17.8ms（单次超 vsync 16.66ms）+ URP.WaitForPresent avg 3.56ms + Semaphore.WaitForSignal avg 17.78ms，三个 slice 是父子重叠（Gfx.WaitForPresentOnGfxThread ⊂ URP.WaitForPresent），用已剥洋葱的 self 值归因。
>
> 关键数字：waitSliceTotalMs/sleepingMs 口径>100%（691%）是因为父子 slice 重叠，用 byState.S pctOfOffCpu=89.34% 做宏观归因，单次 avgMs 做微观强度判定。详见 §6 GPU-bound 判定。
